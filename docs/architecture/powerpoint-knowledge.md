# PowerPoint knowledge documents

PowerPoint originals remain in private object storage. The original preview offers a PDF rendition and the indexed text; downloading still returns the uploaded file. Both views use existing knowledge-base permissions. Presentations renamed without an extension remain identifiable by their stored MIME type.

PDF renditions are generated by the internal `document-converter` service (Gotenberg/LibreOffice). It has no public port in production, no application credentials or storage mount, and an internal Docker network shared only with the app and worker. Outbound document references, webhooks and URL downloads are denied; Chromium routes are disabled. The process is limited to 1 GiB, one CPU, 128 processes and four queued conversions. App-side input/output limits are 64 MiB, requests time out after 75 seconds, and the bounded in-memory preview cache holds at most 32 MiB/eight renditions. Every request is authorized before consulting this cache. Files are never sent to an external Office viewer.

AnyDoc continues to extract native presentation text, tables and speaker notes in presentation order. When the configured RAG OCR is enabled, it receives rendered slides, including composed diagrams, rather than only embedded image assets. The configured slide limit and a 64 MiB rendered-image budget apply. Rendering failures retain native extraction and report a warning while falling back to embedded images. Warnings are retained on the document. Truncated native extraction is rejected rather than silently accepted as complete.

Reindexing a retained original schedules source extraction, rechunking and embedding. The worker prepares the complete replacement before atomically replacing chunks; failure leaves previous chunks and the original intact. A durable flag survives queue retries. Documents without retained originals continue to re-embed existing content. This does not change document IDs, filenames, ownership or access grants.

Deployment applies migration `0066_document_source_extraction` and starts the converter automatically through the existing Coolify Compose workflow. For local development, start `document-converter` from `docker-compose.dev.yml` and set `DOCUMENT_CONVERTER_URL=http://localhost:13000` in the app/worker environment. Existing uploaded presentations need **Reindex** once to benefit from source extraction changes.

Validation includes a synthetic two-slide fixture with reversed slide-file order, Unicode, a table, a chart and speaker notes; real LibreOffice conversion runs in CI, alongside database replacement/permission tests and browser preview/download/indexed-text tests. OCR requires a configured vision model and remains subject to its accuracy and usage limits. Fonts missing from the converter and PowerPoint-specific effects can differ in the PDF; animations are represented as static slides.
